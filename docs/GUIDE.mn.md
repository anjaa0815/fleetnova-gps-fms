## 1. Систем юунаас бүрдэх вэ

```
Хөтөч (вэб UI) ──HTTPS──▶ ┌──────────────────────────────┐        ┌──────────┐
                           │  FLEETNOVA (нэг Node процесс) │ ◀────▶ │ MongoDB  │
GPS төхөөрөмж ──TCP 5027──▶│  • вэб UI + REST API          │        └──────────┘
 (Teltonika)               │  • GPS хүлээн авагч           │
GPS төхөөрөмж ──TCP 5023──▶│  • сануулга, имэйл/SMS ажилтан│ ──▶ SMTP / SMS үйлчилгээ
 (Concox GT06)             └──────────────────────────────┘
Утасны апп ───HTTP(S)────▶  /api/gps/osmand
```

- **Нэг програм** вэб хуудас, API, GPS хүлээн авагчийг бүгдийг агуулна. Тусдаа frontend сервер хэрэггүй.
- **MongoDB** нь production-д заавал хэрэгтэй. Хөгжүүлэлт, туршилтад MongoDB-гүйгээр JSON файл ашиглана (`server/data/`).
- **Traccar** (200+ протокол) нь заавал биш. Өөр үйлдвэрийн төхөөрөмж хэрэглэх бол л хэрэгтэй (README-ийн "Traccar" хэсэг).
- Төхөөрөмжүүд **түүхий TCP** порт (5027, 5023) руу холбогддог. Энэ нь хаана байрлуулахыг шийддэг чухал нөхцөл (4-р бүлэг).

## 2. Өөрийн компьютер дээр нээж үзэх (15 минут)

Хамгийн хялбар, үнэгүй арга. Систем таны компьютер дээр ажиллана, өөр хүнд харагдахгүй.

### 2.1 Хэрэгтэй зүйлс

| Хэрэгсэл | Яаж суулгах |
|---|---|
| **Node.js 22** (LTS) | https://nodejs.org → "LTS" хувилбар. Суулгасны дараа терминал нээж `node -v` гэж бичиж `v22...` гарч байгааг шалгана. |
| **Git** | https://git-scm.com/downloads |

Windows дээр "Терминал" эсвэл "PowerShell", Mac дээр "Terminal" програмыг ашиглана.

### 2.2 Татаж аваад ажиллуулах

```bash
git clone https://github.com/anjaa0815/fleetnova-gps-fms.git
cd fleetnova-gps-fms
npm install
npm run dev
```

- `npm install` ~10–60 секунд (интернэтээс сан татна).
- `npm run dev` ажиллаж эхэлмэгц терминалд `FLEETNOVA SERVER RUNNING` гэж гарна.
- Хөтчөөс **http://localhost:3000** хаягийг нээнэ.

Анх асахад систем жишээ өгөгдөл (Монгол компаниуд, машин, жолооч, рейс, түлш, засвар) өөрөө үүсгэнэ. MongoDB суулгах шаардлагагүй, өгөгдөл `server/data/fleetnova_store.json` файлд хадгалагдана.

> **Энэ хэсгийн алхмуудыг цэвэр татсан хуулбар дээр шалгасан:** `npm install` → `npm run dev` → `http://localhost:3000` нээгдэж, `admin@fleetnova.com` нэвтэрч байна.

### 2.3 Нэвтрэх жишээ хаягууд

| Үүрэг | Имэйл | Нууц үг | Юу харах вэ |
|---|---|---|---|
| Админ (1-р байгууллага) | `admin@fleetnova.com` | `admin123` | Бүх хэсэг, тохиргоо, хэрэглэгч нэмэх |
| Менежер | `manager@fleetnova.com` | `manager123` | Админтай ойролцоо, хэрэглэгч нэмэхгүй |
| Жолооч | `driver@fleetnova.com` | `driver123` | Зөвхөн өөрийн рейс, мэдэгдэл |
| 2-р байгууллагын админ | `altan@fleetnova.com` | `altan123` | Өөр компани: 1-р байгууллагын өгөгдлийг харахгүй |
| **Платформын эзэн** | `superadmin@fleetnova.com` | `super123` | Байгууллага үүсгэх, түдгэлзүүлэх, төлөвлөгөө солих. Компаниудын өгөгдлийг **харахгүй** |

Нэвтрэх хуудсан дээрх **MN / EN** товчоор хэлийг солино. Хөгжүүлэлтийн горимд нэвтрэх хуудсанд "Quick demo" товчнууд байдаг (production-д автоматаар нуугдана).

### 2.4 Ажиллаж байхад хэрэг болох зүйлс

| Хүсэлт | Яаж |
|---|---|
| Зогсоох | Терминалд `Ctrl + C` |
| Дахин асаах | `npm run dev` |
| Өгөгдлийг эхнээс нь болгох | Зогсоож `server/data/fleetnova_store.json` файлыг устгаад дахин асаана (жишээ өгөгдөл дахин үүснэ) |
| Утаснаас (ижил WiFi) харах | Mac/Linux: `HOST=0.0.0.0 npm run dev` · Windows PowerShell: `$env:HOST="0.0.0.0"; npm run dev`, дараа нь утсанд `http://<компьютерийн-IP>:3000` |
| Порт 3000 завгүй | `PORT=3100 npm run dev` (Windows: `$env:PORT="3100"; npm run dev`) |
| Автомат тестүүд | `npm test` (73 тест, ~1–2 минут) |

### 2.5 Заавал биш: MongoDB-тэй туршиж үзэх

Docker суулгасан бол:

```bash
docker run -d --name fn-mongo -p 27017:27017 mongo:7
MONGODB_URI=mongodb://127.0.0.1:27017/fleetnova REQUIRE_MONGODB=true npm run dev
```

(Windows PowerShell: `$env:MONGODB_URI="mongodb://127.0.0.1:27017/fleetnova"; $env:REQUIRE_MONGODB="true"; npm run dev`.) `REQUIRE_MONGODB=true` нь холбогдож чадахгүй бол чимээгүйхэн JSON файл руу шилжихийн оронд шууд алдаа өгнө.

## 3. Системийг тойрч үзэх

Зүүн талын цэс таны үүргээс хамаарч өөр байна. Админаар (`admin@fleetnova.com`) нэвтэрч доорх дарааллаар үзвэл бүхэл зургийг харна.

1. **Хяналтын самбар** — машин, жолооч, рейсийн товч дүн, үнэлгээ, газрын зураг. Тракер холбогдсон бол газрын зураг дээр жинхэнэ байршил харагдана.
2. **Тээврийн хэрэгсэл**, **Жолооч нар**, **Рейсүүд** — бүртгэл, төлөв (Available / On Trip / Maintenance). Рейс эхлүүлэхэд машин, жолооч автоматаар "On Trip" болно.
3. **Шатахууны удирдлага, Засвар, Зардал**, **Шинжилгээ**, **Тайлан** — бүртгэл, графикууд, CSV татах. Түлш/засвар нэмэхэд зардал автоматаар бүртгэгдэнэ.
4. **GPS төхөөрөмж** — төхөөрөмж бүртгэх, онлайн төлөв, "Замын түүх".
5. **Геозон** — газрын зураг дээр тойрог/олон өнцөгт зурж бүс тогтооно.
6. **GPS тайлан** — өдөр/7 хоног/сар сонгож нийт км, рейс, зогсолт, хоосон асаалт, хурд хэтрэлт, түлшний зарцуулалт. CSV татна.
7. **Мэдэгдлүүд → GPS Alerts** — геозонд орох/гарах, хурд хэтрэх сануулга.
8. **Тохиргоо** — байгууллагын мэдээлэл, хурдны хязгаар, имэйл/SMS сувгууд, хэрэглэгч нэмэх, төлөвлөгөө, ашиглалт.
9. **FleetAI туслах** — Gemini ашигладаг. `GEMINI_API_KEY` оруулаагүй бол ажиллахгүй.

### 3.1 GPS-ийг "амьд" харах (төхөөрөмжгүйгээр)

Симулятор хуурамч машиныг Улаанбаатар → Дархан чиглэлд жолоодуулж байршил илгээнэ.

1. Админаар нэвтэрнэ → **GPS төхөөрөмж** → "Төхөөрөмж нэмэх".
   - Нэр: дурын (жишээ нь `Туршилтын тракер`)
   - Протокол: **Teltonika (TCP)**
   - IMEI: 15 орон, жишээ нь `356307042441013`
   - Тээврийн хэрэгсэл: жагсаалтаас сонгоно (нэг машинд нэг тракер)
2. Өөр терминал нээж (сервер ажиллаж байх ёстой), хавтас дотроо:
   ```bash
   npm run simulate -- --imei 356307042441013
   ```
3. Хэдэн секундын дараа төхөөрөмж **онлайн** болж, **Хяналтын самбар**-ийн газрын зураг дээр машин хөдөлнө. "Замын түүх" товчоор замнал зурагдана.
4. Геозон зурж, **Тохиргоо**-д хурдны хязгаар (жишээ нь 60 км/ц) тавиад симуляторыг `--speed 120`-оор ажиллуулбал **Мэдэгдлүүд → GPS Alerts**-д "Хурд хэтэрсэн" сануулга гарна.
5. Дараа нь **GPS тайлан** руу орж хугацаа сонговол км, рейс, зогсолт тооцогдсон байна.

Симуляторын тохиргоо: `--protocol gt06` (Concox), `--interval 5` (секунд), `--speed 60` (км/ц).

> Имэйл/SMS хараахан тохируулаагүй үед сануулгууд "симуляцитай" горимоор зөвхөн серверийн терминалд (`[Email:simulated]`, `[SMS:simulated]`) бичигдэнэ. Жинхэнээр илгээхийг 7-р бүлгээс үзнэ.

## 4. Серверт байрлуулах (production)

### 4.1 Хаана байрлуулах вэ

| Сонголт | Тохиромж |
|---|---|
| **VPS (виртуал сервер)** — Ubuntu 22.04 / 24.04, 2 цөм, 2–4 GB RAM-аас эхэлнэ | **Санал болгож буй зам.** GPS төхөөрөмжүүд түүхий TCP порт (5027, 5023) руу холбогддог, VPS дээр эдгээр портыг шууд нээж болно. |
| Вэб хостинг үйлчилгээ (PaaS) | Вэб UI болон API-г ажиллуулж болох ч үйлчилгээ бүр түүхий TCP-г өөр аргаар (эсвэл огт) дэмждэг. Таны сонгосон үйлчилгээний TCP дэмжлэгийг заавал шалгана. Төхөөрөмжүүд зөвхөн HTTP-ээр (OsmAnd, Traccar forward) холбогдох бол асуудалгүй. |

VPS-ийг ямар ч найдвартай нийлүүлэгчээс (DigitalOcean, Hetzner, Vultr, дотоодын хостинг...) авч болно. Үнэ, байршлыг та өөрөө харьцуулна. Төхөөрөмж байрладаг орны ойролцоох дата төв удаашралыг багасгана.

Мөн **домэйн нэр** хэрэгтэй (жишээ нь `fleet.танай-домэйн.mn`).

### 4.2 Бэлтгэл

1. VPS авч, Ubuntu суулгана. `ssh root@<сервер-IP>`-ээр нэвтэрнэ.
2. Домэйны DNS тохиргоонд **A бичлэг** нэмнэ: `fleet` → серверийн IP. (Хэдэн минутаас хэдэн цаг хүртэл тархана; `ping fleet.танай-домэйн.mn` серверийн IP-г харуулж байвал бэлэн.)
3. Docker суулгана (албан ёсны суулгагч):
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
4. Галт хана (зөвхөн хэрэгтэй портуудыг нээнэ):
   ```bash
   ufw allow 22/tcp      # SSH
   ufw allow 80/tcp      # HTTP (HTTPS гэрчилгээ авахад)
   ufw allow 443/tcp     # HTTPS
   ufw allow 5027/tcp    # Teltonika тракер
   ufw allow 5023/tcp    # GT06 / Concox тракер
   ufw enable
   ```
   **MongoDB-ийн порт (27017)-ийг хэзээ ч интернэтэд нээж болохгүй.** Манай тохиргоонд ч нээгдээгүй.

### 4.3 Системийг суулгах

```bash
git clone https://github.com/anjaa0815/fleetnova-gps-fms.git
cd fleetnova-gps-fms
cp .env.production.example .env.production
nano .env.production        # доорх 4.4-ийн дагуу бөглөнө
```

Эхлүүлэх:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Анхны build 3–10 минут үргэлжилнэ. Дараа нь:

```bash
docker compose -f docker-compose.prod.yml ps          # app, mongo, caddy гурвуулаа "running" байх ёстой
docker compose -f docker-compose.prod.yml logs -f app # "FLEETNOVA SERVER RUNNING", "MongoDB Connected Successfully"
curl https://fleet.танай-домэйн.mn/api/health         # {"success":true,...,"status":"operational"}
```

Caddy HTTPS гэрчилгээг автоматаар авч, шинэчилнэ (DNS зөв, 80/443 порт нээлттэй байх ёстой).

Хөтчөөс `https://fleet.танай-домэйн.mn` нээж, `.env.production`-д бичсэн `ADMIN_EMAIL` / `ADMIN_PASSWORD`-оор нэвтэрнэ. Энэ нь **платформын эзэн** эрх. Production-д жишээ өгөгдөл, "Quick demo" товч **байхгүй**, хоосон систем харагдана.

> `docker-compose.prod.yml`-ийн бүтцийг `docker compose config`-оор шалгасан бөгөөд `Dockerfile` нь CI-д build хийгддэг. Харин **жинхэнэ серверт бүтэн ажиллуулж үзээгүй** тул эхний байрлуулалтын үед 9-р бүлгийг гар дээрээ байлгаарай.

### 4.4 `.env.production` бөглөх

Заавал бөглөх 5 мөр:

| Хувьсагч | Утга |
|---|---|
| `DOMAIN` | `fleet.танай-домэйн.mn` |
| `APP_BASE_URL` | `https://fleet.танай-домэйн.mn` (имэйл доторх холбоос үүгээр үүснэ) |
| `JWT_SECRET` | Урт санамсаргүй текст. Үүсгэх: `openssl rand -hex 48`. **Нууц байлга**, солибол бүх хэрэглэгч дахин нэвтэрнэ |
| `ADMIN_EMAIL` | Таны имэйл (платформын эзэн) |
| `ADMIN_PASSWORD` | 8-аас дээш тэмдэгт, хүчтэй нууц үг |

Үлдсэнийг (SMTP, SMS, Gemini) 7-р бүлгээс үзнэ. `.env.production` файлыг **хэзээ ч git-д оруулж болохгүй** (`.gitignore` нь хаасан).

`MONGODB_URI`, `REQUIRE_MONGODB`, `TRUST_PROXY` нь `docker-compose.prod.yml` дотор өөрөө тохируулагдсан тул дахин бичих шаардлагагүй.

### 4.5 Шинэчлэх

```bash
cd fleetnova-gps-fms
git pull
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Өгөгдөл `mongo-data` volume-д байдаг тул шинэчлэлтээр алга болохгүй. Шинэчлэхийн өмнө 8.1-ийн нөөцлөлтийг хийж байгаарай.

### 4.6 Нөөц хувилбар (production-д заавал)

Орон нутгийн санамсаргүй зүйлээс хамгаалах цорын ганц арга. Нөөцийг **өөр газар** (өөр сервер, S3 төрлийн хадгалалт, өөрийн компьютер) хадгална.

```bash
# нөөцлөх (өдөр бүр cron-оор ажиллуулж болно)
docker compose -f docker-compose.prod.yml exec -T mongo mongodump --db fleetnova --archive --gzip > fleetnova-$(date +%F).archive.gz

# сэргээх
docker compose -f docker-compose.prod.yml exec -T mongo mongorestore --archive --gzip --drop < fleetnova-2026-10-05.archive.gz
```

Нөөцөөс сэргээж үзсэний дараа л "нөөцтэй" гэж үзнэ. Нэг удаа сэргээлтийг туршиж үзээрэй.

### 4.7 Аюулгүй байдлын шалгах жагсаалт

- [ ] `JWT_SECRET` урт, санамсаргүй, нууц
- [ ] `ADMIN_PASSWORD` хүчтэй; нэвтэрсний дараа **Миний профайл**-аас солих нь зүйтэй
- [ ] MongoDB-ийн порт интернэтэд нээгдээгүй (`docker compose ... ps`-д `27017->` гарахгүй)
- [ ] `SEED_DEMO_DATA` тохируулаагүй (тохируулбал `admin123` гэх мэт нийтэд мэдэгдэх нууц үгтэй демо хэрэглэгч үүснэ)
- [ ] Нөөцлөлт ажиллаж, нэг удаа сэргээж үзсэн
- [ ] Имэйл тохируулсан (хэрэглэгч бүртгэл баталгаажуулах, нууц үг сэргээхэд хэрэгтэй)
- [ ] Teltonika/GT06 төхөөрөмжүүд нууцлалгүй TCP ашигладаг: боломжтой бол галт хана дээр төхөөрөмжүүдийн SIM-ийн IP хаягаар хязгаарла

## 5. GPS төхөөрөмж холбох

**Дараалал:** (1) системд төхөөрөмжийг бүртгэнэ → (2) төхөөрөмжийг серверт заана. Бүртгээгүй төхөөрөмжийн өгөгдлийг сервер хүлээн авахгүй.

### 5.1 Бүртгэх

**GPS төхөөрөмж** → "Төхөөрөмж нэмэх". Протоколыг төхөөрөмжийн төрлөөр сонгоно:

| Төхөөрөмж | Протокол | Идентификатор | Хаашаа холбогдох |
|---|---|---|---|
| Teltonika (FMB/FMC/FMT гэх мэт) | Teltonika (TCP) | IMEI, 15 орон | `<сервер>`:**5027** TCP |
| Concox / GT06 төрлийн | GT06 / Concox (TCP) | IMEI, 15 орон | `<сервер>`:**5023** TCP |
| Утасны апп (OsmAnd, Traccar Client) | OsmAnd / Traccar Client (HTTP) | 6–32 тэмдэгт (үсэг, тоо, `-`, `_`) | Бүртгэсний дараа гарах URL (нууц түлхүүртэй) |
| Бусад үйлдвэр (200+) | Via Traccar server | Traccar-ийн `uniqueId` (ихэвчлэн IMEI) | Traccar серверт (README-ийн Traccar хэсэг) |

Нэг машинд нэг тракер холбоно. IMEI нь **бүх платформ дээр давтагдахгүй** (өөр байгууллага ижил IMEI бүртгэж чадахгүй).

### 5.2 Төхөөрөмжийг тохируулах

- **Teltonika**: Teltonika Configurator → GPRS тохиргоо → "Server settings" (хувилбараас хамаарч цэсийн нэр өөр байж болно): Domain = `fleet.танай-домэйн.mn` (эсвэл серверийн IP), Port = `5027`, Protocol = **TCP**. Codec 8 / 8 Extended-ийг дэмжинэ.
- **Concox/GT06**: ихэвчлэн SMS тушаалаар сервер (домэйн эсвэл IP) болон порт `5023`-ыг зааж өгнө. Тушаалын формат загвараас хамаарах тул төхөөрөмжийн гарын авлагаас харна.
- Төхөөрөмж SIM-д дата (APN) идэвхтэй байх ёстой.

### 5.3 Ажиллаж байгааг шалгах

1. **GPS төхөөрөмж** хуудсанд төхөөрөмж ~1–2 минутын дотор **онлайн** болж, сүүлийн байршил харагдана.
2. Серверийн лог: `docker compose -f docker-compose.prod.yml logs -f app`.
3. Тракер байгаа газар нь **GPS-ийн дохиотой** байх ёстой (дохиогүй "0,0" байршлыг систем хаяна).

> **Анхааруулга:** Teltonika болон Concox протоколыг **жинхэнэ төхөөрөмжөөр шалгаагүй** (тест, симулятороор л шалгасан). Анхны жинхэнэ төхөөрөмжөөр туршихдаа нэг төхөөрөмжөөс эхэлж, лог дээр харж байгаарай.

### 5.4 Асуудал гарвал

| Шинж тэмдэг | Шалтгаан |
|---|---|
| Төхөөрөмж хэзээ ч онлайн болохгүй | IMEI системд бүртгэгдээгүй / буруу протокол сонгосон / галт хана 5027, 5023-ыг хаасан / SIM-д дата байхгүй / төхөөрөмж буруу порт руу заасан |
| Онлайн ч газрын зураг дээр цэг алга | GPS дохио байхгүй (0,0), эсвэл машинтай холбоогүй |
| Байршил удаан шинэчлэгдэнэ | Төхөөрөмжийн илгээх интервал урт (төхөөрөмжийн тохиргоо) |

### 5.5 Төхөөрөмж рүү команд илгээх

**GPS төхөөрөмж** хуудсанд төхөөрөмж бүрийн мөрөнд терминалын дүрстэй товч байна (Teltonika, Concox, Traccar төхөөрөмж дээр). Үүгээр:

- **Байршлыг одоо авах**, **Төхөөрөмжийг дахин эхлүүлэх**: администратор, менежер.
- **Хөдөлгүүрийг зогсоох / сэргээх**: **зөвхөн администратор**.

Команд "Хүлээж байна → Илгээсэн → Гүйцэтгэсэн" төлвөөр явна. Төхөөрөмж холбоогүй бол команд хүлээнэ (30 минут, хөдөлгүүрийнх 10 минут), дараа нь хугацаа дуусна. Төхөөрөмж хариулаагүй бол "Илгээсэн, гэвч хариулсангүй" гэж тэмдэглэгдэнэ (олон реле хариулдаггүй, команд ажилласан байж болно).

**Хөдөлгүүрийн командыг аюулгүй байлгах** (хөдөлгүүр зогсоох нь ослын шалтгаан болж болно):

1. Төхөөрөмжийн тохиргоонд (Засах) администратор "**Хөдөлгүүрийн реле суулгасан, туршсан**" гэж идэвхжүүлнэ. Анхдагчаар унтраалттай. Реле холбосон, трекер тохируулсан, машин дээр туршсаны дараа л идэвхжүүлнэ.
2. Командыг илгээхдээ **машины улсын дугаарыг бичиж** баталгаажуулна.
3. Хөдөлгүүрийг зогсоохыг **зөвхөн машин зогсож байгаа нь тодорхой үед** зөвшөөрнө (сүүлийн хурд 5 км/ц-ээс бага, байршил 10 минутаас шинэ). Илгээх мөчид дахин шалгана: хүлээж байх хооронд машин хөдөлсөн бол **илгээгдэхгүй**. Сэргээх команд хэзээ ч хориглогдохгүй.
4. Хүсэлт бүр түүхэнд (хэн, хэзээ, юу) үлдэж, серверийн логт бичигдэнэ.

> **Анхааруулга:** жинхэнэ трекер, релеэр шалгаагүй. Реле хэрхэн холбогдсоноос (Teltonika-ийн ямар дижитал гаралт, "асаалттай" нь хөдөлгүүрийг таслах уу) болон трекерийн загвараас команд өөр байдаг тул `TELTONIKA_ENGINE_STOP_COMMAND` гэх мэт хувьсагчаар солино (10-р бүлэг). Эхлээд нэг машинаар, хамгаалагдсан газар туршиж, мөн машиныг түгжих эрх (гэрээ, хууль) танд байгаа эсэхийг шалгаарай.

## 6. Үйлчлүүлэгч байгууллага нэмэх

Систем олон байгууллагатай (multi-tenant): байгууллага бүр өөрийн өгөгдөл, хэрэглэгч, төхөөрөмжтэй бөгөөд бусдынхыг харахгүй.

### 6.1 Хоёр арга

1. **Үйлчлүүлэгч өөрөө бүртгүүлнэ**: нэвтрэх хуудсан дээрх "Энд бүртгүүлэх" холбоос → байгууллагын нэр, нэр, имэйл, нууц үг. 14 хоногийн туршилтын (trial) төлөвлөгөөтэй админ үүснэ. Имэйл тохируулсан бол имэйлээр баталгаажуулах холбоос явна.
2. **Та (платформын эзэн) үүсгэнэ**: `ADMIN_EMAIL`-ээр нэвтэрч → **Байгууллагууд** → шинэ байгууллага үүсгэж төлөвлөгөө, админы имэйл, нууц үгийг оруулна.

### 6.2 Төлөвлөгөө

| Төлөвлөгөө | Машин | Хэрэглэгч | Төхөөрөмж | Имэйл/өдөр | SMS/өдөр | Байршил хадгалах |
|---|---|---|---|---|---|---|
| Trial (14 хоног, үнэгүй) | 10 | 5 | 10 | 50 | 20 | 30 хоног |
| Basic | 50 | 20 | 50 | 300 | 100 | 90 хоног |
| Pro | 500 | 200 | 500 | 2 000 | 500 | 365 хоног |
| Enterprise | хязгааргүй | хязгааргүй | хязгааргүй | хязгааргүй | хязгааргүй | 730 хоног |

Төлөвлөгөөг **Байгууллагууд** хуудсанд солино. Trial дууссан байгууллага зөвхөн унших горимд орно, түдгэлзүүлсэн байгууллага нэвтэрч чадахгүй (төхөөрөмжүүдийн өгөгдөл хүлээн авахаа ч зогсооно). Хадгалах хугацааг `POSITION_RETENTION_DAYS`-аар бүгдэд нь дарж болно.

### 6.3 Төлбөр авах (QPay)

Байгууллагын админ зүүн цэсний **Төлбөр** хэсгээс Basic эсвэл Pro багц, хугацаа (1/3/6/12 сар) сонгож QPay QR кодоор эсвэл банкны апп-аар төлнө. Төлбөр орсон даруйд цонх өөрөө шинэчлэгдэж, багц идэвхжиж, имэйлээр баримт очно.

1. QPay-тэй merchant гэрээ хийж, `QPAY_USERNAME`, `QPAY_PASSWORD`, `QPAY_INVOICE_CODE`-оо авна. Эхлээд QPay-ийн **sandbox** хаягаар (`QPAY_BASE_URL=https://merchant-sandbox.qpay.mn/v2`) туршина.
2. `.env.production`-д эдгээрийг болон үнийг (`PLAN_PRICE_BASIC`, `PLAN_PRICE_PRO`, сард ногдох төгрөг) бичиж `up -d`-ээр дахин асаана. Анхдагч үнэ (49 000 / 199 000 ₮) **түр утга** тул өөрийнхөөрөө солино.
3. `APP_BASE_URL` нь интернэтээс QPay-д хүрдэг `https://` хаяг байх ёстой, учир нь QPay төлбөр орсныг тэр хаягаар мэдэгдэнэ.
4. Төлбөр хийх горим Төлбөр хуудсанд харагдана: `qpay` (бодит), `simulated` (QPay тохируулаагүй, production биш бөгөөд сервер зөвхөн localhost-д сонсож байгаа үед, `npm run dev`-ийн үндсэн байдал: "Төлсөн гэж тэмдэглэх (туршилт)" товч, мөнгө хөдөлдөггүй), `disabled` (production-д QPay тохируулаагүй: онлайн төлбөр унтраалттай).
5. Төлбөр орсныг сервер QPay-ээс өөрөөс нь лавлаж баталгаажуулдаг (мэдэгдэлд итгэдэггүй). Мэдэгдэл алдагдсан ч 5 минут тутамд ажилтан дахин шалгана.

Багцын хугацаа дууссаны дараа 3 хоногийн хөнгөлөлт, дараа нь данс зөвхөн унших горимд орно (төлбөр хийх боломж үргэлж нээлттэй). Хугацаа сунгахад одоогийн хугацааны төгсгөлөөс үргэлжилнэ, өөр багц руу шилжвэл өнөөдрөөс эхэлнэ (хуучин багцын үлдэгдэл шилжихгүй).

> **Анхааруулга:** QPay-тэй жинхэнээр шалгаагүй (sandbox эрх олдоогүй), QPay-ийн API-г mock серверээр шалгасан. Ажиллуулахаасаа өмнө sandbox дээр заавал туршина уу. Мөн **ебаримт (НӨАТ-ын баримт)**, буцаалт, автомат сунгалт, хөнгөлөлт хараахан байхгүй.

### 6.4 Байгууллагын өөрийн нэвтрэх хуудас

`https://fleet.танай-домэйн.mn/?org=<slug>` хаяг тухайн байгууллагын нэр, лого, өнгөтэй нэвтрэх хуудсыг нээнэ. `slug` нь байгууллагын нэрээс үүсдэг. Лого, өнгийг байгууллагын админ **Тохиргоо**-д өөрчилнө. Өөрийн дэд домэйн (`acme.fleet.mn`) хараахан дэмжигдээгүй.

### 6.5 Байгууллагын хэрэглэгчид

Байгууллагын админ **Тохиргоо** хэсгээс хэрэглэгч (менежер, жолооч) нэмнэ. Хэрэглэгч бүр профайлдаа имэйл/SMS сануулга авах эсэхээ сонгоно.

## 7. Имэйл болон SMS тохируулах

Тохируулаагүй бол имэйл, SMS **зөвхөн серверийн логт** бичигдэнэ ("симуляци"), хэнд ч очихгүй.

### 7.1 Имэйл (SMTP)

`.env.production`-д:

```
SMTP_HOST=smtp.gmail.com          # жишээ нь Gmail; өөрийн нийлүүлэгчийнхээ утгыг бичнэ
SMTP_PORT=587
SMTP_SECURE=false                 # 465 порт бол true
SMTP_USER=you@gmail.com
SMTP_PASS=<апп-нууц-үг>
EMAIL_FROM=FLEETNOVA <you@gmail.com>
```

- Gmail-д энгийн нууц үг биш, "App password" (2 шатлалт баталгаажуулалт асаасны дараа үүсгэнэ) хэрэгтэй.
- Үйлчлүүлэгчдэд олноор илгээх бол SMTP-ийг тусгайлсан имэйл үйлчилгээгээр (Mailgun, SendGrid, Amazon SES гэх мэт) хийвэл spam-д орох эрсдэл багатай.
- **Анхаарах:** `SMTP_HOST` тохируулмагц **шинэ бүртгэл имэйлээр баталгаажуулалтгүйгээр нэвтэрч чадахгүй** болно (`REQUIRE_EMAIL_VERIFICATION=false`-ээр унтраана). Нууц үг сэргээх имэйл ч зөвхөн SMTP тохируулсан үед үнэхээр илгээгдэнэ.
- Шалгах: нэвтэрч **Тохиргоо** хуудасны "Сануулга хүргэлт (Имэйл ба SMS)" карт дээрх "Надад туршилтын мессеж илгээх" товчийг дарна.

### 7.2 SMS

`SMS_PROVIDER=twilio` (болон `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM`) эсвэл `SMS_PROVIDER=http` (өөрийн эсвэл дотоодын SMS гарцад `{to, text, from}` JSON-ыг `SMS_HTTP_URL` руу POST хийнэ, `SMS_HTTP_TOKEN` нь Bearer токен). Монгол дугаар (8 орон) автоматаар `+976` болно, өөр улсын код бол `SMS_DEFAULT_COUNTRY_CODE`-ийг тохируулна. Кирилл SMS нь UCS-2 тул 70 тэмдэгт тутамд нэг мессеж гэж тооцогдоно.

Дараа нь байгууллагын админ **Тохиргоо** хуудасны "Сануулга хүргэлт (Имэйл ба SMS)" картанд имэйл/SMS сувгийг асааж, хэрэглэгч бүр **Миний профайл** дээрээ "Сануулгын мэдэгдэл" хэсэгт сануулга хүлээн авахаа идэвхжүүлнэ.

> Жинхэнэ SMTP, Twilio, SMS гарцаар шалгаагүй (mock серверээр л шалгасан).

### 7.3 FleetAI (заавал биш)

Google Gemini API түлхүүрээ `GEMINI_API_KEY`-д бичнэ. Түлхүүр зөвхөн серверт байх бөгөөд хөтчид гарахгүй.

## 9. Алдаа засах

| Шинж тэмдэг | Шалтгаан, шийдэл |
|---|---|
| `JWT_SECRET environment variable is required in production` | `.env.production`-д `JWT_SECRET` бичээгүй |
| `app` контейнер дахин дахин унана, логт `MongoDB connection failed` | `mongo` контейнер асаагүй. `docker compose ... ps`, `... logs mongo`. `REQUIRE_MONGODB=true` тул холбогдохгүй бол зориуд унадаг |
| Хөтчид "сайт хүрэх боломжгүй" | DNS хараахан тархаагүй, 80/443 порт хаалттай (`ufw status`), `DOMAIN` буруу бичсэн |
| HTTPS гэрчилгээ гарахгүй | Домэйн серверийн IP руу заагаагүй. `docker compose ... logs caddy` |
| Нэвтрэхэд `403 EMAIL_NOT_VERIFIED` | `SMTP_HOST` тохируулсан тул имэйл баталгаажуулалт шаардлагатай. Имэйл ирэхгүй бол SMTP-г шалга, эсвэл түр `REQUIRE_EMAIL_VERIFICATION=false` |
| Нууц үг сэргээх имэйл ирэхгүй | SMTP тохируулаагүй (логт `[Email:simulated]` харагдана) эсвэл spam хавтас. Таны имэйл системд бүртгэлтэй байх ёстой |
| Олон удаа буруу нууц үг бичсэн, "түр хүлээнэ үү" | Хамгаалалт. Данс+IP хослолыг 15 минут түгжинэ |
| Төхөөрөмж онлайн болохгүй | 5.4 |
| `EADDRINUSE` (порт завгүй), өөрийн компьютер дээр | Өөр програм 3000 / 5027 / 5023 портыг ашиглаж байна. `PORT=3100 npm run dev`, `GPS_TCP_PORT=5127`, `GT06_TCP_PORT=0` (унтраах) |
| `Vehicle limit reached for your plan` | Төлөвлөгөөний хязгаарт хүрсэн. **Байгууллагууд**-аас төлөвлөгөө сольно |
| Нэвтрэх, бүртгүүлэх "Too many requests" | Хамгаалалтын хязгаар. Хэдэн минут хүлээнэ |
| Өөрийн компьютер дээр `npm install` алдаа | Node хувилбар хуучин. `node -v` нь 22 эсвэл 20.19+ байх ёстой |

Лог дотор `[Email:simulated]` / `[SMS:simulated]` гарч байвал тухайн суваг тохируулагдаагүй гэсэн үг.

## 10. Тохиргооны хувьсагчдын жагсаалт

Production-д `.env.production` файлд, өөрийн компьютер дээр орчны хувьсагчаар (`.env` файл ч болно) өгнө.

|---|---|

| `PORT` / `HOST` | Вэб порт (`3000`) / сонсох хаяг (`localhost`; Docker-т `0.0.0.0`) |
| `JWT_SECRET` | **Production-д заавал.** Хөгжүүлэлтэд байхгүй бол процесс бүр түр түлхүүр үүсгэнэ |
| `MONGODB_URI` | MongoDB холбоос. Байхгүй бол `server/data/` JSON файл (зөвхөн хөгжүүлэлт) |
| `REQUIRE_MONGODB` | `true` бол MongoDB-д холбогдож чадахгүй үед унана (JSON руу шилжихгүй) |

## 11. Юу шалгагдаагүй байгаа вэ

Шударгаар хэлэхэд эдгээрийг **жинхэнээр туршаагүй**. Анхны байрлуулалтдаа анхаарна уу:

- **Жинхэнэ GPS төхөөрөмж** (Teltonika, Concox), Traccar сервер. Зөвхөн тест болон симулятороор шалгасан. Протоколын задлалтыг баримтад тулгуурлан хийсэн.
- **Жинхэнэ SMTP, Twilio, SMS гарц.** Mock серверээр л шалгасан.
- **Төхөөрөмжийн команд (хөдөлгүүр зогсоох гэх мэт).** Жинхэнэ трекер, релеэр шалгаагүй, mock трекерээр л шалгасан (5.5).
- **QPay.** Sandbox, бодит merchant эрхгүйгээр бичсэн тул mock QPay серверээр л шалгасан (6.3).
- **`docker-compose.prod.yml`-г жинхэнэ серверт.** Бүтцийг `docker compose config`-оор, `Dockerfile`-г CI-д build хийж шалгасан.
- **MongoDB Atlas, replica set** (үүл дэх MongoDB). Локал MongoDB 7 болон CI-ийн `mongo:7` дээр шалгасан.
- **Хэмжээ.** Нэг шахмал машин дээр хэмжсэн үр дүн (8.2). Мянга мянган төхөөрөмжийн бодит ачааллыг шалгаагүй.
- **Ебаримт (НӨАТ)**, буцаалт, автомат сунгалт, мобайл апп, өөрийн дэд домэйн, 2 шатлалт нэвтрэлт: хараахан байхгүй.
- Ганц Node процесс: хэдэн сервер ажиллуулах бол TCP портыг L4 balancer-аар хуваах хэрэгтэй (бодит дэд бүтцийн ажил).
