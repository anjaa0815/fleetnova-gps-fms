# CLIXGPS-ийг серверт байрлуулах: алхам алхмаар заавар

Энэ заавар **сервер огт үзээгүй хүнд** зориулагдсан. Дээрээс нь дарааллаар нь хийвэл 1–2 цагт систем интернэтэд гарна. Тайлбар, тохиргооны дэлгэрэнгүйг `docs/GUIDE.mn.md`-ийн 4, 8, 9-р бүлгээс харна.

> **Анхааруулга:** `docker-compose.prod.yml`-ийн бүтцийг шалгасан, `Dockerfile` CI-д build хийгддэг. Харин **жинхэнэ серверт бүтэн ажиллуулж үзээгүй**. Тиймээс эхний байрлуулалтыг ажлын өдөр, яарахгүй цагт хийж, 9-р алхмын алдаа засах хэсгийг гар дээрээ байлгаарай. Жинхэнэ трекер, QPay, имэйл/SMS-ийг мөн тусад нь шалгана (алхам 12).

## Юу хэрэгтэй вэ

| Зүйл | Тайлбар |
|---|---|
| Сервер (VPS) | Ubuntu 24.04 (эсвэл 22.04), **2 vCPU, 4 GB RAM, 40 GB диск**-ээс эхэлнэ. Hetzner, Vultr, Hostinger VPS гэх мэт аль ч нийлүүлэгч болно. **Заавал "VPS/Cloud" төрөл, вэб хостинг биш**: трекерүүд 5027, 5023 порт руу шууд холбогдох тул порт нээх эрх хэрэгтэй. |
| Домэйн нэр | жишээ нь `clixgps.mn` эсвэл `fleet.clixgps.mn` |
| Имэйл хаяг | SMTP (Gmail, Brevo, Mailgun...) бүртгэл баталгаажуулах, нууц үг сэргээхэд |
| Өөрийн компьютер | Windows бол **PowerShell**, Mac/Linux бол **Terminal** |

## 1. Сервер захиалах

1. Нийлүүлэгчийн сайтад бүртгүүлж, **шинэ сервер** үүсгэнэ.
2. Үйлдлийн систем: **Ubuntu 24.04**.
3. Хэмжээ: дээрх доод хэмжээ. Дараа нь томруулж болно.
4. Нэвтрэх арга: **SSH key** сонговол аюулгүй (алхам 2). Хэрэв нууц үгээр нэвтрэх бол нийлүүлэгчийн өгсөн root нууц үгийг хадгална.
5. Үүсгэсний дараа серверийн **IP хаяг**-ыг тэмдэглэнэ (жишээ нь `203.0.113.10`).
6. Нийлүүлэгчийн хяналтын самбарт **firewall** байвал (Hetzner Cloud Firewall гэх мэт) эсвэл тусдаа тохируулаагүй бол алхам 5-ын портуудыг нээх шаардлагатай эсэхийг шалгана.

## 2. Серверт нэвтрэх

SSH key үүсгээгүй бол өөрийн компьютер дээр (нэг удаа):

```bash
ssh-keygen -t ed25519
```

Нийтийн түлхүүрийг (`~/.ssh/id_ed25519.pub`) сервер үүсгэхдээ нийлүүлэгчид өгнө. Дараа нь:

```bash
ssh root@203.0.113.10
```

Анх удаа "continue connecting?" гэвэл `yes` гэнэ.

## 3. Домэйныг серверт заах

Домэйн бүртгүүлсэн газрынхаа **DNS тохиргоо**нд:

| Төрөл | Нэр | Утга |
|---|---|---|
| A | `fleet` (эсвэл `@`, хэрэв үндсэн домэйнийг ашиглах бол) | серверийн IP |

Тархахад хэдэн минутаас хэдэн цаг болно. Шалгах:

```bash
ping fleet.clixgps.mn
```

Серверийн IP харагдаж байвал бэлэн. **Үүнгүйгээр HTTPS гэрчилгээ авч чадахгүй** тул 6-р алхмаас өмнө заавал хүлээнэ.

> Байгууллага бүрт өөрийн хаяг (`kargo.clixgps.mn`) өгөх бол DNS-д **wildcard** `*` нэрээр мөн адил A бичлэг нэмнэ. Дэлгэрэнгүйг GUIDE 6.4-өөс харна. Wildcard HTTPS-д нэмэлт тохиргоо хэрэгтэй тул эхний байрлуулалтад заавал биш.

## 4. Сервер бэлтгэх

Серверт нэвтэрсэн байхад:

```bash
# 1) системийг шинэчилнэ
apt update && apt -y upgrade

# 2) аюулгүй байдлын шинэчлэлтийг автоматаар суулгана
apt -y install unattended-upgrades ufw git
dpkg-reconfigure -plow unattended-upgrades     # асуувал "Yes"

# 3) Docker суулгана (албан ёсны суулгагч)
curl -fsSL https://get.docker.com | sh
docker --version && docker compose version     # хоёулаа хувилбар харуулах ёстой
```

## 5. Галт хана

**Эхлээд SSH-г нээнэ, дараа нь идэвхжүүлнэ** (эс бөгөөс өөрийгөө серверээс түгжинэ):

```bash
ufw allow 22/tcp      # SSH
ufw allow 80/tcp      # HTTP (HTTPS гэрчилгээ авахад)
ufw allow 443/tcp     # HTTPS
ufw allow 5027/tcp    # Teltonika трекер
ufw allow 5023/tcp    # GT06 / Concox трекер
ufw enable            # "y"
ufw status
```

**MongoDB-ийн порт 27017-г хэзээ ч нээхгүй.** Манай тохиргоонд интернэтэд нээгдээгүй, зөвхөн апп дотроосоо хандана.

## 6. Системийг татаж, тохируулах

```bash
cd /opt
git clone https://github.com/anjaa0815/fleetnova-gps-fms.git clixgps
cd clixgps
cp .env.production.example .env.production
nano .env.production
```

`nano` дотор: сумаар явж засна, **Ctrl+O, Enter** хадгална, **Ctrl+X** гарна.

Заавал бөглөх 5 мөр:

```
DOMAIN=fleet.clixgps.mn
APP_BASE_URL=https://fleet.clixgps.mn
JWT_SECRET=<доорх тушаалын гаралтыг буулгана>
ADMIN_EMAIL=<таны имэйл>
ADMIN_PASSWORD=<8-аас дээш тэмдэгттэй хүчтэй нууц үг>
```

`JWT_SECRET` үүсгэх (өөр цонхонд эсвэл `nano`-оос гарч):

```bash
openssl rand -hex 48
```

Энэ утгыг **нууцалж**, нууц үгийн менежерт хадгална. Солибол бүх хэрэглэгч дахин нэвтрэнэ.

Имэйл (SMTP) бөглөх нь **маш чухал**: бүртгэл баталгаажуулах, нууц үг сэргээх имэйл үүгээр явна. Тохиргоо GUIDE 7.1-д бий. Хоосон бол имэйл зөвхөн серверийн логт бичигдэж, хэнд ч очихгүй.

Файлыг хамгаална:

```bash
chmod 600 .env.production
```

## 7. Эхлүүлэх

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Анхны build **3–10 минут** үргэлжилнэ. Дуусмагц:

```bash
docker compose -f docker-compose.prod.yml ps
```

`app`, `mongo`, `caddy` гурвуулаа `running` (эсвэл `Up`) байх ёстой. Мөн `mongo` мөрөнд `27017->` **гарахгүй**.

## 8. Ажиллаж байгааг шалгах

```bash
docker compose -f docker-compose.prod.yml logs --tail=50 app
curl https://fleet.clixgps.mn/api/health
```

- Логт `CLIXGPS SERVER RUNNING` болон `MongoDB Connected Successfully` харагдана.
- `curl` нь `"status":"operational"` бүхий JSON буцаана.
- Хөтчөөс `https://fleet.clixgps.mn` нээгдэж, 🔒 тэмдэгтэй байна.

Алхам 6-д бичсэн `ADMIN_EMAIL` / `ADMIN_PASSWORD`-оор нэвтэрнэ. Энэ нь **платформын эзэн (super admin)**. Хоосон систем харагдана (production-д демо өгөгдөл байхгүй). Нэвтэрсэн даруйдаа **Миний профайл**-аас нууц үгээ солино.

Дараа нь **Байгууллагууд** хуудсанд эхний үйлчлүүлэгчээ нэмнэ (GUIDE 6-р бүлэг).

## 9. Алдаа гарвал

| Шинж тэмдэг | Шалгах |
|---|---|
| Хөтөч нээгдэхгүй, "гэрчилгээний алдаа" | DNS зөв эсэх (`ping`), 80/443 нээлттэй эсэх, `docker compose ... logs caddy`. Гэрчилгээ авч чадаагүй бол Caddy логт шалтгаан бичнэ |
| `app` байнга дахин асаж байна | `docker compose ... logs app`. Ихэнхдээ `.env.production`-д `JWT_SECRET` / `ADMIN_PASSWORD` дутуу |
| `docker compose` тушаал олдохгүй | Алхам 4-ийн Docker суулгалт бүтэн дууссан эсэх |
| Дахин асаалгах | `docker compose -f docker-compose.prod.yml --env-file .env.production restart` |
| Бүгдийг зогсоох (өгөгдөл үлдэнэ) | `docker compose -f docker-compose.prod.yml down` |

> **Хэзээ ч** `down -v` бүү ажиллуул: `-v` нь өгөгдлийн сан бүхий volume-ийг устгана.

Бусад алдааг GUIDE 9-р бүлгээс харна.

## 10. Нөөцлөлт (заавал)

Нөөцийг **өөр газар** хадгалахгүй бол сервер сүйрэхэд хамт алга болно.

Өдөр бүр автоматаар нөөцлөх (серверт):

```bash
mkdir -p /opt/backups
cat > /opt/backup.sh <<'EOF'
#!/bin/sh
cd /opt/clixgps
docker compose -f docker-compose.prod.yml exec -T mongo mongodump --db fleetnova --archive --gzip > /opt/backups/clixgps-$(date +%F).archive.gz
# 14-өөс хуучин нөөцийг устгана
find /opt/backups -name 'clixgps-*.archive.gz' -mtime +14 -delete
EOF
chmod +x /opt/backup.sh
( crontab -l 2>/dev/null; echo "30 3 * * * /opt/backup.sh" ) | crontab -
/opt/backup.sh && ls -lh /opt/backups
```

Дараа нь нөөцийг серверээс **өөр газар** (өөрийн компьютер, өөр сервер, S3 төрлийн хадгалалт) тогтмол хуулна, жишээ нь өөрийн компьютероос:

```bash
scp root@203.0.113.10:/opt/backups/clixgps-2026-10-09.archive.gz .
```

Нэг удаа **сэргээж үзэх** нь заавал: нөөцийг туршиж сэргээгээгүй бол "нөөцтэй" гэж тооцохгүй (сэргээх тушаал GUIDE 4.6-д). Мөн нийлүүлэгчийн **автомат snapshot/backup** үйлчилгээг нэмж идэвхжүүлэх нь зүйтэй.

## 11. Шинэчлэх

```bash
cd /opt/clixgps
/opt/backup.sh                      # эхлээд нөөцөлнө
git pull
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
docker compose -f docker-compose.prod.yml logs --tail=30 app
```

Өгөгдөл `mongo-data` volume-д байдаг тул шинэчлэлтээр алга болохгүй.

## 12. Гарахын өмнөх шалгалт

Жинхэнэ үйлчлүүлэгчид өгөхөөс өмнө (GUIDE 4.7 ба 11-р бүлэг):

- [ ] Нэвтэрч, нууц үгээ сольсон
- [ ] Туршилтын байгууллага үүсгэж, имэйл **хүрч байгааг** шалгасан (бүртгэл баталгаажуулах, нууц үг сэргээх)
- [ ] **Жинхэнэ трекер**-ээс GPS ирж, газрын зураг дээр харагдсан (GUIDE 5-р бүлэг)
- [ ] QPay ашиглах бол **sandbox**-оор нэг төлбөр бүтэн гүйцэтгэсэн, дараа нь жинхэнэ ключ тавьсан
- [ ] Нөөцлөлт ажиллаж, нэг удаа сэргээж үзсэн
- [ ] `SEED_DEMO_DATA` тохируулаагүй
- [ ] Серверт зөвхөн 22, 80, 443, 5027, 5023 порт нээлттэй (`ufw status`)

## Хавсралт A. Hetzner / Vultr / Hostinger-ийн онцлог

Заавар бүх нийлүүлэгчид ижил. Ялгаа нь зөвхөн сервер үүсгэх хэсэгт:

- **Hetzner Cloud:** Cloud Console → Add Server → Ubuntu 24.04 → 2 vCPU / 4 GB-ийн хэмжээ. Firewall үүсгэвэл 22, 80, 443, 5027, 5023-ыг нээнэ. Бүртгэлийн баталгаажуулалт хатуу байж болно.
- **Vultr:** Deploy → Cloud Compute → Ubuntu 24.04 → 2 vCPU / 4 GB. Нийлүүлэгчийн firewall тохируулсан бол мөн портуудыг тэнд нээнэ; үгүй бол алхам 5-ын `ufw` хангалттай.
- **Hostinger:** **VPS** төрлийг сонго (энгийн вэб хостинг биш). Ubuntu 24.04 (эсвэл "Ubuntu 24.04 with Docker" загвар байвал Docker суулгах алхам 4-ийн 3-р хэсгийг алгасна). Хяналтын самбарынх нь firewall байвал портуудыг нээнэ.

## Хавсралт B. Coolify (өөрөө эзэмшдэг самбар)

Coolify нь серверт суулгадаг, GitHub-аас автоматаар шинэчилдэг, нөөцлөлт/SSL-ийг самбараас удирдах боломжтой. Харин **түүхий TCP порт (5027, 5023)-ыг гаргах, MongoDB-г тусад нь тохируулах** нэмэлт алхам шаардана, мөн энэ төсөл дээр туршаагүй. Тиймээс эхний байрлуулалтад дээрх энгийн замыг (Docker Compose) санал болгоно; тогтвортой болсны дараа Coolify руу шилжиж болно.

## Хавсралт C. Хэр удаан, хэр зардалтай вэ

- Анхны суулгалт: 1–2 цаг (DNS тархахыг хүлээх хугацаа тусдаа).
- Сарын зардал: сервер (тарифаас хамаарна, нийлүүлэгчийнхээ үнийг шалгана) + домэйн (жилд) + нөөцлөлтийн үйлчилгээ (сонголттой) + SMS/QPay-ийн шимтгэл.
- Нэг сервер ~500 төхөөрөмжийн ачааллыг тестэд даасан (GUIDE 8.2). Өсөхөд серверийг томруулна.
